# Second Approach Report — 20 October 2026

## New approach

We tested two extensions to the real-only baseline for classifying 200 bird species in CUB-200-2011:

- **Standard augmentation:** 2,000 real images plus one fixed crop/flip version of each, giving 4,000 training entries.
- **Synthetic data:** the same 2,000 real images plus 2,000 images generated by Stable Diffusion 1.5 from species-name prompts, also giving 4,000 entries. This run used the original synthetic pool before manual quality filtering, without crop/flip augmentation.

## Motivation

With only 10 real images per species, additional training examples may improve generalization. Standard augmentation varies framing and orientation. Synthetic images may add new appearances and backgrounds, but can depict the wrong species or contain visual defects. We compare both methods to test whether generated data improves performance beyond ordinary augmentation.

## Implementation

Standard augmentation uses a random resized crop covering 50–100% of the source image, resized to 224 × 224, and a horizontal flip with probability 0.5. A seed derived from the image ID and run seed fixes each additional view across accesses and data-loader workers. Views are recreated during loading rather than stored as additional image files. The transform restores the random-number-generator state afterwards so it does not affect other randomness.

The mixed-data loader reads generated images from a manifest containing image IDs, labels, paths and SHA-256 hashes. It verifies labels and file hashes before training and loads images on demand. Both comparison datasets combine originals and additional entries in one shuffled loader, with a fixed shuffle seed.

Real originals, synthetic images and validation images share the baseline preprocessing: RGB conversion, aspect-ratio-preserving resize of the shorter side to 256 pixels, center crop to 224 × 224, tensor conversion and ImageNet normalization. Only the standard arm's additional views use random crop/flip. Validation contains only real images and uses no random augmentation or shuffling.

All runs use the same real subset (`train_10shot_seed0.csv`) and initialization seed (0), ImageNet-pretrained ResNet-18 with frozen backbone and BatchNorm statistics, and a trainable 512-to-200 linear head. Training uses cross-entropy and AdamW with learning rate 0.001, weight decay 0.0001, batch size 64, and 1,000 optimizer steps. Validation runs every 100 steps on the same 1,000 real images, five per species. The checkpoint with the highest validation macro F1 is retained.

The fixed step budget prevents the larger datasets from receiving extra optimizer steps. It does not equalize passes through each dataset: in the synthetic arm, approximately half the sampled entries are generated images, reducing real-image presentations compared with the baseline.

## Initial results

Best-checkpoint validation results, seed 0:

| Approach | Training entries | Macro F1 | Accuracy | Macro-F1 change vs. baseline | Training + validation |
| --- | ---: | ---: | ---: | ---: | ---: |
| Real-only baseline | 2,000 | 53.15% | 53.30% | — | 7.41 min |
| Real + standard augmentation | 4,000 | 53.54% | 53.70% | +0.39 percentage points | 24.22 min |
| Real + synthetic, original pool | 4,000 | 48.16% | 48.90% | −4.99 percentage points | 8.86 min |

Standard augmentation improved macro F1 by 0.39 percentage points; the original synthetic pool reduced it by 4.99 points. These are results from one seed and validation-selected checkpoints; more seeds are needed to assess consistency. No classifier test metrics were computed.

We verified all 1,000 validation image IDs, labels and class names, recomputed aggregate and per-class metrics from saved predictions, and checked the best-step selection against training history. Configuration checks confirmed matching real-subset and validation-manifest hashes and shared training settings. The comparison table is saved in [results_summary.csv](../reports/classifier/results_summary.csv).

Training times include periodic validation and checkpoint saves on an RTX 4060 Laptop GPU with mixed precision. They exclude preparation and generation; generating the synthetic pool took approximately 97 minutes on an RTX 3070.

Subsequent manual review marked 1,120 generated images as `ok`, 320 as `artifact` (correct species with visual defects), 536 as `wrong_species`, and 24 as `not_a_bird`. Incorrect labels may contribute to the synthetic result, but this has not been established experimentally.

**Next step:** use the reviewed pool without additional generation. The merged selection fix retains up to 10 accepted images per species, including incomplete groups. Keeping `ok` and `artifact` gives 1,440 synthetic images before further leakage exclusions: a prospective total of 3,440 training entries. Training on this pool is pending. Its results must be distinguished from the original-pool run above because both quality and quantity change, and synthetic counts vary across species.
